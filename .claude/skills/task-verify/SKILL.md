# task-verify

Перевіряє все, що змінила гілка відносно `origin/main`, і видає вердикт.
Знахідки йдуть у підсумок, а виправляє їх той, хто викликав перевірку.

## 0. Обсяг

`git fetch origin`, потім `git diff --stat origin/main...HEAD` і `git status --short`.
Незакомічені зміни - теж знахідка: перевіряється лише закомічене.
За списком файлів визначити, які з розділів 2-4 обов'язкові; пропущений розділ іде в підсумок з причиною.

## 1. Команди

`npm run typecheck`, `npm run lint`, `npm test`, `npm run build` - кожна окремо, до кінця, навіть якщо попередня впала.
Помилка будь-якої - FAIL.
Попередження lint і консолі збірки - теж знахідки, навіть не з цієї гілки.
Тест, що падає не завжди, перезапустити один раз, щоб це підтвердити; нестабільний тест - знахідка.

## 2. Проходження в браузері

Обов'язкове, якщо зачеплено те, що бачить дитина чи дорослий: `src/components`, `src/screens`, `src/styles`, `src/content`, `src/audio`, `public/`, `index.html`.

- `npm run dev` у фоні, адресу взяти з його виводу.
- Будь-який доступний браузерний інструмент, вікно 390×844 (ширина телефона).
- Пройти змінений сценарій від головного екрана так, як пройшла б його дитина, у **обох режимах**: «Сама/Сам» і «З дорослим».
  Режим перемикається в «Для дорослих» (кнопку на головному екрані утримувати) → число словами ввести цифрами → «Хто поруч».
- Потрібний стан (відкриті букви, записи) створювати через сам застосунок: розділ «Для дорослих» або імпорт резервної копії.
- Будь-що, що виглядає не так (обрізаний текст, зсув, горизонтальна прокрутка, накладання, помилка в консолі), - знахідка, навіть якщо гілка цього не чіпала.

Якщо браузерного інструмента немає, розділ іде в «не вдалося перевірити», а не в PASS.

## 3. Принципи методики

Обов'язкова, якщо зачеплено контент, вправи чи екрани.
Звірити дифф з кожним пунктом розділу «Принципи методики» з `CLAUDE.md` і в підсумку відмітити кожен окремо: дотримано, порушено (де саме) або не стосується.
Порушений принцип - FAIL, навіть якщо тести зелені.
Слова й склади лише з уже вивчених букв перевіряють тести контенту; якщо такий тест упав, у знахідці сказати, що виправляти треба контент.

## 4. Сумісність зі збереженим прогресом

Обов'язкова, якщо зачеплено формат стану чи кешування: `src/logic/progress.ts`, `src/store/`, `src/logic/backup.ts`, `src/audio/db.ts`, `public/sw.js`, ідентифікатори місій у `src/content/course.ts`.

- Стан збереження з `origin/main` читається новою версією без втрат: на це є тест зі старим форматом, і він проходить.
  Немає тесту - знахідка.
- Перейменований ідентифікатор місії лишив старий як відповідник нового.
- Резервна копія, зроблена версією з `origin/main`, імпортується.
- Змінився набір файлів у кеші `sw.js` - змінено й назву кешу, а `activate` прибирає старі кеші, тож стара версія не застрягне в телефоні.

## 5. Підсумок

```
task-verify: PASS | FAIL

Команди: typecheck ✓ lint ✓ test ✓ build ✓
Браузер: <сценарій>, «Сама» ✓, «З дорослим» ✓ | не потрібно: <чому>
Методика: <кожен принцип - ✓ / ✗ де / не стосується> | не потрібно: <чому>
Сумісність: <кожна перевірка - ✓ / ✗> | не потрібно: <чому>

Знахідки:
- <файл:рядок або екран> - <що не так>

Не вдалося перевірити:
- <що> - <чому>
```

FAIL - якщо хоч одна перевірка не пройшла або список знахідок не порожній, зокрема знахідки поза диффом гілки.
PASS - лише з порожнім списком знахідок; «не вдалося перевірити» на вердикт не впливає, але завжди показується поруч із ним.
