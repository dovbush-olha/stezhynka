# /finish [номер issue]

Бере гілку з уже закоміченою реалізацією і веде її до PR.
Кожен крок перевірки робить свіжий помічник (Agent), щоб погляд не був прив'язаний до того, як код писався.
Зупинятися лише там, де потрібне рішення користувачки, а все інше вирішувати самій і йти далі.

## 1. Передумови

- Гілка не `main`, `git status --short` порожній, `git log --oneline origin/main..HEAD` не порожній (після `git fetch origin`).
  Незакомічені зміни - спитати, чи закомітити їх, і не йти далі без відповіді.
- Номер issue: з аргументу, інакше `#<номер>` з повідомлень комітів гілки, інакше спитати.
  Прочитати issue: `gh issue view <номер> --json title,body`.

## 2. Маршрут

Прочитати повний дифф `git diff origin/main...HEAD` і для кожного кроку з таблиці вирішити: потрібен чи ні.
Показати маршрут таблицею: крок, потрібен / пропущено, чому (з посиланням на файли диффу).
Одразу переходити до кроків.

| Крок | Коли потрібен |
| --- | --- |
| `doubt-driven-development` | нетривіальна логіка: нові чи змінені рішення в `src/logic`, `src/store`, `src/audio`, `public/sw.js`, `scripts/`; не перейменування і не лише дані контенту |
| `code-simplification` | змінено код (`.ts`, `.tsx`, `.js`, `.mjs`, `.css`), а не лише дані контенту чи документацію |
| `security-and-hardening` | лише якщо зачеплено імпорт резервної копії (`src/logic/backup.ts`, `src/audio/backup.ts`, `src/components/Backup.tsx`) чи записи голосу (`src/audio/recordings.ts`, `src/audio/readings.ts`, `src/audio/db.ts`, `scripts/import-voice.mjs`) |
| `mattpocock-skills:code-review` | завжди; база `origin/main`, специфікація - issue |
| `task-verify` | завжди, останнім |

`doubt-driven-development`, `code-simplification` і `security-and-hardening` - особисті скіли з `addyosmani/agent-skills`, у репозиторії їх немає.
Крок, чий скіл у цій сесії недоступний, позначити «пропущено: скіл не встановлено» - він потрапить у текст PR.

## 3. Кроки

По одному, у порядку таблиці: кожен наступний бачить виправлення попереднього.
Для кожного - окремий помічник з таким дорученням:

- мета кроку й назва скіла, який треба викликати першою дією;
- база `origin/main`, номер і заголовок issue, тека worktree;
- виправлення, що не потребують рішення, внести самому, перевірити `npm run typecheck`, `npm run lint` і тестами зачепленого модуля, і закомітити окремим комітом українською з погляду користувача;
- повернути: що виправлено (коміти), що лишилося і чому, і окремо - питання, які потребують рішення користувачки, з варіантами.

Питання помічника - через `AskUserQuestion`; відповідь передати новому помічнику того самого кроку.
Між кроками коротко сказати користувачці, що зроблено і що далі.

## 4. task-verify

Помічник викликає `task-verify` і повертає його підсумок повністю.
FAIL - новий помічник виправляє знахідки (так само окремими комітами), потім `task-verify` знову, доки не буде PASS.
Знахідки поза диффом гілки теж виправляються, якщо це не потребує рішення.
Те, що без рішення користувачки не виправити, - через `AskUserQuestion`.

## 5. Push і PR

Показати підсумок: маршрут, коміти кроків (`git log --oneline origin/main..HEAD`), вердикт `task-verify` зі списком «не вдалося перевірити».
Зупинитися й спитати дозволу на push - це перша дія, яку бачать інші.
Після дозволу:

1. `git push -u origin <гілка>`.
2. Текст PR - скілом `mattpocock-skills:pr`, українською; у тексті - маршрут (зокрема пропущені кроки й чому), вердикт `task-verify` і «не вдалося перевірити»; наприкінці `Closes #<номер>`.
3. `gh pr create --title "<заголовок з погляду користувача>" --body-file <файл у scratchpad>`.
4. Дати користувачці посилання на PR.
